Bus Reliability Modeling

Modeling the Effect of the RapidRide Program on Bus Reliability in Seattle, WA

My master's thesis for the QMSS program was a study of whether a bus upgrade program (RapidRide) in Seattle, WA, was effective at improving reliability on the routes that it upgraded. This question is pertinent because no such analysis previously existed (as far as I can tell, King County Metro primarily uses 'percentage of trips on-time' as the KPI for bus reliability performance). My analysis used traditional regression approaches as well as Bayesian Additive Regression Trees (BARTs), a machine learning approach, to estimate a treatment effect, in seconds, of applying the RapidRide upgrade to a bus route. This page is dedicated to that project--in addition to posting the final thesis paper, I intend to periodically add supplemental materials that outline parts of the process that did not make it into the final paper.

I began the project by collecting real-time arrival data for RapidRide and non-RapidRide bus stops across the city. I achieved this by writing a Python script that requested real-time General Transit Specification Feed (GTFS) data from the city and stored it in a JSON format. I then automated this process to run every 15 minutes with AWS Lambda and stored the resulting JSON files to an S3 Storage Bucket, which I then periodically downloaded to my local machine and stored in a PostgreSQL database. The data cleaning process involved adding scheduled arrival times (to calculate how much a bus deviated from its scheduled arrival time) and adding pretreatment covariates for use as adjustment variables in my final models. One aspect of the pretreatment covariate process that I'm particularly pleased with is how I used GIS in R to associate census block group data with the geographic shape of each bus route. For model fitting computational reasons, I took a sample of 100k observations for use in my training/test datasets.

I then fit some multivariate linear models using the `rstanarm` package in R, using a RapidRide indicator variable as my treatment variable. In order to potentially capture more complex interaction effects and nonlinear relationships without dealing with inflated standard errors, I also fit a BART model. For the BART modeling, I used Google Vertex AI for virtual machine access since my local machine was a bit underpowered for the task. This involved using a custom Dockerfile along with my R script to properly set up the virtual machine to do my work. Finally, I used the models to calculate factual and counterfactual estimates of reliability and compared the two for my final treatment effect. The benefit of using `rstanarm` and BARTs was that I got Bayesian posterior distributions for the effect, which gave me a better picture of the effect, generally speaking. The analysis showed that the RapidRide upgrade did improve reliability, though the mean estimates for this effect varied between ~10 seconds for the linear models and ~45 seconds for the BART model.

In addition to the final paper submission, I presented this as a 3-minute talk to a general audience as part of the GSAS SynThesis Competition. Out of 12 finalists, I placed in 3rd!
